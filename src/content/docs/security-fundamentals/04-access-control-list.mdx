# Access Control List IPv4

ACL memeriksa paket dari atas ke bawah dan berhenti pada **ACE pertama yang cocok**. Jika tidak ada ACE yang cocok, implicit `deny any` di bagian akhir menolak paket.

## Standard dan extended ACL

| Jenis | Field utama | Pedoman penempatan |
| --- | --- | --- |
| Standard IPv4 ACL | alamat sumber | dekat tujuan |
| Extended IPv4 ACL | sumber, tujuan, protokol, dan port | dekat sumber |

Pedoman tersebut bukan aturan mutlak. Pilih lokasi berdasarkan topologi, jalur paket, dampak pada traffic lain, dan kemampuan operasional tim.

## Mulai dari kebutuhan

Skenario: subnet siswa `192.168.10.0/24` hanya boleh mengakses HTTPS pada server `172.16.10.10`. Traffic siswa memasuki router melalui `G0/0`.

```text
ip access-list extended SISWA_HTTPS
 10 permit tcp 192.168.10.0 0.0.0.255 host 172.16.10.10 eq 443
 90 deny ip any any log
exit

interface GigabitEthernet0/0
 ip access-group SISWA_HTTPS in
```

Extended ACL dapat ditempatkan dekat sumber karena mampu memeriksa tujuan dan port. Wildcard `0.0.0.255` mewakili subnet `/24`.

<Callout type="remember">
ACL yang sudah dibuat belum aktif sampai diterapkan pada interface dan arah yang benar menggunakan `ip access-group NAMA in|out`.
</Callout>

## Verifikasi sebelum menyatakan selesai

```text
show access-lists SISWA_HTTPS
show ip interface GigabitEthernet0/0
```

Uji traffic yang memang dirancang oleh ACL. Jika rule dibuat untuk HTTPS, jangan hanya membuktikannya menggunakan ping. Pastikan traffic permit dan deny sama-sama diuji, kemudian cocokkan hasilnya dengan hit counter.
